# Перенос с REG.Cloud на FirstByte

Статус на 16.11.2026: код обновлён локально, аккаунт FirstByte зарегистрирован.
Новый VPS не заказан: доступность выбранного тарифа в биллинге не подтвердилась.
Работающий сервер REG.Cloud пока не изменяется. Для переноса нужны IP нового VPS,
SSH-пользователь и доступ по ключу.

## Конфигурация

На публичной витрине был выбран MSK-KVM-SSD: 1 vCPU, 1 ГБ RAM, 20 ГБ SSD,
Москва, 189 ₽/месяц. После регистрации прямая ссылка заказа этого тарифа выдала
«Тариф не соответствует дата-центру». В списке доступных дата-центров нет Москвы.
Проверенная форма заказа KVM-SSD-1-FIN VL показывает Финляндию, 1 vCPU, 1 ГБ RAM,
10 ГБ SSD и итоговую цену 429 ₽/месяц. Она не оплачена: это другая цена и конфигурация.
До решения пользователя или уточнения доступности у провайдера перенос не выполняется.
Официальная страница: https://firstbyte.ru/vps-vds/kvm-ssd/ .
FAQ: https://firstbyte.ru/info/faq/ . Актуальные цену, регион и включённые опции необходимо
проверять в форме заказа: данные витрины и FAQ не подтвердили доступность тарифа за 189 ₽.

У первоначально выбранной конфигурации памяти и ядер столько же, сколько было в Free Tier;
диска вдвое больше. У проверенной доступной конфигурации в Финляндии диск 10 ГБ.
Тип диска, доступная доля CPU и нагрузка соседей отличаются, поэтому скорость проверяется
после запуска. 1 ГБ — небольшой запас при работающем Chromium для Profi.ru.

При создании выбрать Ubuntu 24.04 LTS x86_64, без панели управления сайтами.
Добавить публичный SSH-ключ с компьютера; приватный ключ и пароли в чат не передавать.
Установить Docker Engine и Compose plugin по официальной инструкции для Ubuntu:
https://docs.docker.com/engine/install/ubuntu/ .
Домен, Nginx и открытые веб-порты боту не нужны.

## До переключения

1. Проверить SSH, версию ОС, свободный диск и память на новом сервере.
2. При необходимости создать swap 1–2 ГБ: он страхует пики, но не заменяет RAM.
3. Загрузить проверенный код в `/opt/freelance-bot`. Для сборки достаточно `src`, `config`,
   `certs`, `pyproject.toml`, `README.md`, `Dockerfile`, `compose.yaml`.
   Секреты `.env`, рабочая база и `.venv` не входят в архив исходного кода.
4. Собрать образ заранее (`docker compose build bot`), пока старый бот продолжает работу.
5. Получить **актуальный `.env` со старого сервера**, а не заменять его локальной копией.
   Сохранить права доступа `chmod 600 .env`. Устаревшие переменные генерации откликов
   можно убрать; новый код их игнорирует.
6. Подготовить свежую копию изменяемых настроек из серверного `config`: рабочий промпт
   может отличаться от локального после `/set filter`. Новый код добавляет правила оценки
   ясности ТЗ самостоятельно, поэтому основной промпт можно сохранить.

Не запускать основной процесс на новом сервере одновременно со старым. Два экземпляра
конкурируют за VK Long Poll и могут отправить дубликаты.

## Переключение с сохранением истории

1. Остановить только контейнер бота на **старом сервере**:

   ```bash
   cd /opt/freelance-bot
   docker compose stop bot
   ```

2. Скопировать со старого сервера весь каталог `data` после остановки. Если есть файлы
   `bot.sqlite3-wal`/`bot.sqlite3-shm`, они также относятся к базе. Оставить отдельную
   резервную копию для отката; исходную рабочую базу не удалять.
3. Перенести актуальные изменяемые настройки из `config` и `.env`.
4. До запуска проверить целостность копии базы и сравнить количество записей проектов,
   просмотренных публикаций, ручных отметок, счётчиков и состояние Gmail IMAP.
5. Запустить новый бот:

   ```bash
   cd /opt/freelance-bot
   docker compose up -d bot
   docker compose ps
   docker compose logs --tail=100 bot
   ```

Новые nullable-поля метаданных и ясности ТЗ добавляются автоматически. Старые записи не
получают выдуманные проценты найма. Просмотренные публикации повторно не рассылаются.

## Проверка после запуска

- Kwork, FL.ru, Profi.ru и Gmail работают с теми же настройками включения, что раньше.
- С нового IP доступны вход в Profi.ru, используемый AI API и VK.
- На новых карточках есть уровень А/Б/В, краткое описание и «Откликнулся».
- Старые кнопки генерации только сообщают об удалённой функции; AI не вызывается.
- Сохранились статистика, история, ручные счётчики, фильтры и отметки просмотренных писем.
- `docker stats --no-stream` и `free -m` не показывают нехватку памяти; контейнер не
  перезапускается из-за OOM. Включён `restart: unless-stopped`.

Не удалять REG.Cloud до успешной проверки. Если нужен откат, сначала остановить новый
контейнер. Если на новом уже появились события, сохранить его базу: запуск старой копии
без переноса новых данных потеряет эти изменения и может повторить уведомления.
Остановка REG.Cloud сама по себе не прекращает оплату диска и IP; удаление ресурса —
отдельный шаг после завершения переноса и сохранения резервной копии.
