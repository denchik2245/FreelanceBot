# VK-бот уведомлений о заказах Kwork, FL.ru и Profi.ru

Бот просматривает общие ленты проектов Kwork и FL.ru во всех категориях. Сначала бесплатный
локальный фильтр отбирает карточки по широкому набору ключевых слов, затем GigaChat оценивает
их по контексту. Подходящие новые проекты отправляются личным сообщением от сообщества VK.

Бот также может получать штатные email-уведомления FL.ru из Gmail и пересылать новые личные
сообщения в VK. Почтовый ящик открывается через IMAP только для чтения: письма не удаляются и
не помечаются прочитанными. Обрабатываются только письма с адресом отправителя в домене `fl.ru`,
а ссылки в уведомлении принимаются только с HTTPS-доменов `fl.ru` и `www.fl.ru`.

В диалоге постоянно доступна нижняя callback-панель с разделами «Настройки», «Статистика»
и «Отклики». Нажатия не создают сообщения от имени пользователя,
а переключение нижней клавиатуры происходит через сразу удаляемое невидимое сообщение.
Навигационные подписи вроде «Выберите действие» и «Настройки уведомлений» в диалог не попадают.
Статистика и отклики используют не более одной видимой информационной панели: при переходе
старая панель удаляется. Настройки разделены на источники уведомлений, фильтры проектов и
AI-тексты. Для каждой биржи уведомления можно отключить независимо. В VK также настраиваются
минимальный AI-балл и минимальный известный бюджет. Проекты без указанного бюджета не
отбрасываются. Значения сохраняются в базе и переживают перезапуск. Статистика показывает
число проектов, признанных подходящими после AI-оценки,
и отдельное число отклонённых AI за 24 часа, 7 и 30 дней.
Кнопка «Очистить чат» в настройках удаляет из диалога старые сообщения бота, не затрагивая
сообщения пользователя и локальную историю проектов в базе данных.
В статистике отображается дата начала отсчёта, а красная кнопка «Очистить статистику» переносит
точку отсчёта на текущий момент, не удаляя историю просмотренных проектов и откликов.

Время публикации выводится без секунд в часовом поясе МСК+2 (UTC+5).
Подпись часового пояса в самом сообщении не показывается. Автоматические уведомления
отправляются только для проектов не старше 24 часов; старые карточки и карточки без даты
молча пропускаются.

У каждой карточки есть кнопка «Откликнулся». После нажатия она становится зелёной с галочкой;
повторное нажатие отменяет выбор без отдельного сообщения. Раздел «Отклики» показывает
только счётчики без списка проектов. Выберите Kwork или FL.ru, затем нажмите «Заказали у другого»,
«Написали мне» или «Заказали» для добавления одного результата. «Отказали» доступно только для FL.ru.
Рядом с каждым результатом есть «−1» для исправления ошибки. Результаты привязаны только к бирже,
а не к конкретному проекту. Если включён Profi.ru или есть его накопленные отклики,
доступна также эта биржа.

В «Откликах» и «Статистике» отображаются общая сводка и отдельные показатели бирж:
конверсии «Откликнулся → Написали мне» и «Откликнулся → Заказали», доля заказов у других,
а для FL.ru ещё доля отказов. Знаменатель — число откликов соответствующей биржи.
При отсутствии откликов процент не рассчитывается. «Написали мне» учитывает факт переписки
и сохраняется после заказа или отказа; отметьте его отдельно, если заказу предшествовала переписка.
Итоговые результаты «Заказали», «Заказали у другого» и «Отказали» взаимоисключающие:
для исправления результата уменьшите прежний счётчик и увеличьте новый.
Количество переписок и суммарное количество итогов не могут превышать число откликов.

«Очистить статистику» в «Откликах» обнуляет все счётчики бирж, сохраняя историю проектов
и отметки на карточках. Сброс статистики подходящих проектов выполняется отдельно.
При обновлении накопленные результаты, включая скрытые записи, переносятся автоматически
один раз; ранее сброшенные записи заново не учитываются.

## Как отбираются проекты

Kwork получает общую выдачу через API мобильного приложения с параметром `all`, а FL.ru читает
общую HTML-ленту заказов `/projects/?kind=1` без вакансий и конкурсов. Обе площадки обходятся
постранично: максимум 10 страниц или до страницы, на которой все распознанные проекты старше
24 часов.

До обращения к GigaChat название, описание и категория проекта проверяются локально. Фильтр
учитывает русские словоформы и варианты написания следующих широких групп:

- сайт, веб, лендинг, интернет-магазин;
- дизайн, редизайн, интерфейс, экраны приложения, UI/UX;
- Figma/Фигма, макет, прототип, юзабилити/usability;
- Tilda, Zero Block, WordPress и WooCommerce.

Фильтр намеренно пропускает сомнительные совпадения: окончательное решение принимает AI по
контексту проекта и правилам отбора. Категория площадки сохраняется, но не ограничивает
выдачу.

AI определяет основную задачу по заголовку и полному описанию. Подходят веб-/UI-дизайн
и его доработка любого размера, аудит дизайна/UX, создание сайтов и магазинов на Tilda
и WordPress, правки Tilda, Figma → Tilda и сайт → Figma. Заказ на создание сайта без
выбранной платформы принимается: можно предложить WordPress. Подробные границы описаны
в `config/prompts/project_filter.txt`.

Дополнительные SEO, графический дизайн и программирование не мешают приёму подходящей
основной задачи. Но самостоятельные заказы на них отклоняются, даже для Tilda/WordPress.
Название платформы не заменяет определение результата заказа.

Новые проекты оцениваются по текущей версии промпта отбора. Уже отправленные уведомления
повторно не рассылаются. При редактировании файлов локально требуется перезапуск бота; замена через
«Настройки → AI-тексты» применяется сразу.
Решение `unclear` не помечает проект окончательно просмотренным. При изменении названия,
описания, категории, бюджета или правил отбора бот оценивает его повторно, пока публикация
остаётся свежей; неизменный заказ не вызывает новый запрос к AI на каждом цикле.

Profi.ru авторизуется в кабинете специалиста и использует сохранённый фильтр аккаунта. Перед
первым API-запросом бот запускает headless Chromium и сохраняет живую страницу кабинета
на всё время работы. Фоновые циклы используют эту сессию последовательно. При закрытии браузера
или ошибке запроса сессия пересоздаётся со свежим входом, а при остановке
бота браузер закрывается. Cookies и browser-state не экспортируются в файлы проекта. Бот
обходит выдачу по cursor-пагинации, извлекает как обычные карточки, так и заказы из каруселей,
объединяет повторения по ID и передаёт их в тот же AI-процесс, что и другие биржи. Поэтому
локальный фильтр ключевых слов для Profi.ru не применяется: набор заказов определяется услугами
аккаунта, например:

- Landing page
- Веб-дизайн
- Макет сайта
- Создание сайта на Tilda
- Создание сайтов

Повторяющиеся карточки объединяются по ID проекта, поэтому сообщение придёт один раз.

## Настройка VK

1. Создайте сообщество VK и включите в нем сообщения.
2. В настройках API сообщества создайте ключ доступа с правом на сообщения.
3. Напишите сообществу любое сообщение от своего аккаунта. Без этого сообщество не сможет
   начать личный диалог.
4. Узнайте числовой ID своего пользователя VK.
5. В настройках сообщества откройте **Сообщения → Настройки для бота** и включите
   **Возможности ботов**. Без этого VK отклоняет сообщения с клавиатурой.
6. Откройте **Работа с API → Long Poll API** и включите Long Poll. Бот автоматически включает
   события **Входящие сообщения** и **Нажатие на callback-кнопку**.

Команда `/menu` повторно показывает панель, если она была скрыта в клиенте VK. Бот пытается
сразу удалить само сообщение `/menu`, чтобы оно не оставалось в диалоге.
Если возможности ботов были включены уже после запуска контейнера, отправьте `/menu` —
перезапускать бот не требуется.

## Запуск

```bash
cp .env.example .env
```

Заполните в `.env`:

- `VK_GROUP_TOKEN` — ключ сообщества;
- `VK_USER_ID` — ваш числовой ID;
- `KWORK_LOGIN` и `KWORK_PASSWORD` — вход в аккаунт Kwork.
- `PROFI_LOGIN` и `PROFI_PASSWORD` — парольный вход в кабинет специалиста Profi.ru; укажите
  обе переменные либо оставьте обе пустыми, чтобы отключить источник.
- `FL_GMAIL_ADDRESS` — Gmail-адрес, на который FL.ru присылает уведомления;
- `FL_GMAIL_APP_PASSWORD` — отдельный 16-значный пароль приложения Google, а не основной
  пароль аккаунта. Обе переменные можно оставить пустыми, чтобы отключить уведомления;
- `AI_PROVIDER` — `gigachat` (по умолчанию) или `deepseek`;
- `GIGACHAT_CREDENTIALS` — ключ авторизации при `AI_PROVIDER=gigachat`;
- `DEEPSEEK_API_KEY` — ключ прямого API при `AI_PROVIDER=deepseek`;
- `AI_ENABLED=true` — включить AI-фильтрацию и генерацию откликов.

## Подключение DeepSeek V4.1 Flash напрямую

1. Зарегистрируйтесь на https://platform.deepseek.com, пополните баланс API
   и создайте отдельный API-ключ для бота. Возможность оплаты конкретной иностранной
   картой проверяется в кабинете. Подписка на чат не заменяет баланс API.
2. Добавьте `DEEPSEEK_API_KEY` в существующий `.env`. Не отправляйте ключ в чат и не
   добавляйте его в Git. Остальные переменные и ключи бота сохраните.
3. Проверьте соединение одним коротким платным запросом:

```bash
docker compose run --rm --no-deps bot python -m freelance_bot.check_deepseek
```

При локальном запуске: `PYTHONPATH=src .venv/bin/python -m freelance_bot.check_deepseek`.
Команда проверяет полный JSON-ответ. HTTP 401 означает неверный ключ, 402 — недостаточный
баланс, 429 — ограничение запросов. Ключ и тела ошибок API не выводятся.

4. Сначала проверьте отбор на существующих размеченных заказах:

```bash
docker compose run --rm --no-deps -e AI_ENABLED=true -e AI_PROVIDER=deepseek bot \
  python -m freelance_bot.evaluate_ai --live --limit 66 \
  --output data/eval-deepseek.json
```

Оценка расходует API-токены, сохраняет отчёт в `data/eval-deepseek.json`, не отправляет
сообщения VK и не меняет рабочую базу. Для проверки откликов добавьте `--responses`.
Оцените ложные допуски и пропущенные подходящие заказы. Исторические отчёты GigaChat
относятся к прежним строгим правилам: сравнение моделей требует одинакового нового
набора и одинаковых правил. Часть примеров уже использовалась при настройке,
поэтому добавьте новые реальные заказы с пользовательской разметкой.

5. Для переключения рабочего бота добавьте в `.env`:

```dotenv
AI_ENABLED=true
AI_PROVIDER=deepseek
DEEPSEEK_FILTER_MODEL=deepseek-flash
DEEPSEEK_FILTER_FALLBACK_MODEL=deepseek-flash
DEEPSEEK_RESPONSE_MODEL=deepseek-flash
```

Затем выполните `docker compose up -d --force-recreate bot`. После обновления зависимостей
или установки новых консольных команд вместо запуска модулей нужен `--build`.
Для возврата к GigaChat установите `AI_PROVIDER=gigachat` и пересоздайте контейнер.

Все три роли по умолчанию используют V4.1 Flash (`deepseek-flash`). Если основная и
резервная модели совпадают, повторной независимой проверки кандидатов нет, даже при
`AI_VERIFY_ACCEPTED=true`. При разных моделях действуют прежние правила перепроверки.
Для начала используйте одну модель и оцените качество отбора до включения рабочего потока.

Клиент явно передаёт `thinking: {"type": "disabled"}` и запрашивает JSON-объект.
DeepSeek JSON mode не гарантирует соответствие схеме: поля решения и отклика,
ID портфолио и текст по-прежнему проверяет код бота. Некорректный ответ вызывает повтор;
непроверенный отклик не показывается. Расход входных, выходных и кешированных токенов
пишется в журнал для каждого ответа. Правила отбора, профиль и портфолио общие для провайдеров.

Документация: https://api-docs.deepseek.com/quick_start/,
https://api-docs.deepseek.com/guides/thinking_mode/.

## Уведомления о сообщениях FL.ru через Gmail

1. Убедитесь, что в FL.ru включены email-уведомления о новых личных сообщениях.
2. Включите двухэтапную аутентификацию Google и создайте отдельный пароль приложения для бота:
   <https://myaccount.google.com/apppasswords>.
3. Добавьте адрес и полученный пароль в `.env`:

```dotenv
FL_GMAIL_ADDRESS=you@gmail.com
FL_GMAIL_APP_PASSWORD=abcdefghijklmnop
FL_MAIL_POLL_INTERVAL_SECONDS=60
```

Пробелы в отображаемом Google пароле можно оставить: при запуске они удаляются автоматически.
Не используйте основной пароль от Google. При первом подключении бот запоминает текущую позицию
INBOX и не присылает старые письма. Затем каждое новое письмо FL.ru отправляется в VK один раз.
Проверка выполняется в режиме `readonly` и использует IMAP-команду `BODY.PEEK[]`, поэтому письмо
остаётся непрочитанным. Если пароль приложения отозван или Gmail временно недоступен, бот один раз
сообщит об ошибке в VK и отдельно уведомит после восстановления соединения.

Проверить пароль приложения и доступ к INBOX без чтения старых писем и без отправки в VK:

```bash
docker compose run --rm bot fl-mail-check
```

AI-конфигурация разделена по задачам:
- `config/prompts/project_filter.txt` — единственный источник критериев поиска для Pro;
- `config/freelancer_profile.txt` — факты о навыках исполнителя, только для откликов;
- `config/portfolio.json` — кейсы: `id`, `name`, `product`, `work`, `platform`, `url`;
- `config/skills/freelance-response/` — полная копия скилла из `C:\My\Code\Skills\freelance-response`,
  включая `SKILL.md`, правила стиля, исходный профиль, индекс и 13 карточек кейсов;
- `config/prompts/response_writer.txt` — адаптация скилла к одному готовому отклику и JSON бота.

Четыре редактируемых файла доступны в **Настройки → AI-тексты**: `/set filter`, `/set profile`,
`/set portfolio`, `/set response`. Новый текст передавайте со следующей строки либо UTF-8
вложением `.txt`/`.json`. Изменения применяются сразу, предыдущий файл сохраняется в `.bak`.
Портфолио проверяется перед записью. При запуске бот сверяет ID и публичные ссылки JSON-каталога
с индексом и карточками скилла. Для нового кейса или смены ссылки обновите каталог, индекс и карточки
и перезапустите бота; `/set portfolio` не позволит записать JSON, расходящийся с карточками.
В запрос модели отклика (DeepSeek или GigaChat) передаются `SKILL.md`, `writing-style.md`,
действующий профиль и предварительно выбранные карточки с данными индекса. Сам API файлы не читает.
Действующий `config/freelancer_profile.txt` содержит цены, сроки, этапы и контакты исходного профиля,
а также ранее подтвержденные дополнительные услуги бота. Исходный профиль сохранен в скилле;
редактирование профиля через VK меняет действующий файл. Файлы скилла читаются при запуске,
после их изменения перезапустите бот. Изменения внешней папки Skills автоматически не переносятся.
Публичные URL подставляет код: для FL.ru используются ссылки FL.ru, для остальных источников —
подтвержденные публичные ссылки Kwork. Контакты Telegram и MAX добавляются из действующего
профиля двумя строками в самом конце только для FL.ru. Цена и срок берутся из подтвержденных
ориентиров, произвольные надбавки не рассчитываются. Для неизвестного объема или неподтвержденных
сведений потребуется уточнить черновик перед отправкой заказчику.
Каталог `./config` подключён к Docker-контейнеру.
Каталог `./src` подключён только для чтения; Python загружает актуальный код из него.
После обновления Python-файлов достаточно `docker compose up -d`. Если менялись
зависимости или базовый образ, выполните `docker compose up -d --build`.
Пути можно переопределить через `AI_FILTER_PROMPT_PATH`, `AI_PROFILE_PATH`,
`AI_PORTFOLIO_PATH`, `AI_RESPONSE_PROMPT_PATH`, `AI_RESPONSE_SKILL_PATH`.
Последняя переменная задает папку полного скилла; индекс и карточки берутся из ее `references`.
JSON-каталог можно хранить отдельно, но ID и ссылки должны совпадать с карточками скилла.

`GIGACHAT_FILTER_MODEL` — основная модель отбора (`GigaChat-2-Pro` по умолчанию).
`GIGACHAT_FILTER_FALLBACK_MODEL` — резерв и независимая перепроверка положительных решений
(`GigaChat-2-Max` по умолчанию).
`GIGACHAT_RESPONSE_MODEL` — модель откликов (`GigaChat-3-Ultra` по умолчанию). Ultra доступна
только физлицам в Freemium-режиме GigaChat API.
Pro возвращает `decision` (`accept`, `reject`, `unclear`), `reason`, `summary`.
Только `accept` отправляется в VK; остальные решения сохраняются без уведомления.
Дословная цитата не требуется: она не доказывала смысловую релевантность и могла ошибочно
отклонить подходящий заказ. При пустом описании модель оценивает смысл заголовка.
Описание передаётся полностью после удаления HTML-разметки: ограничения в 6000 символов
и автоматического отказа по длине нет. Более длинный текст увеличивает расход токенов;
если запрос превысит контекст конкретной модели, ошибка API обработается обычными повторами,
а непроверенное решение не отправится в VK.

Рабочий промпт сначала определяет основной оплачиваемый результат, затем отличает его
от сопутствующих работ. «Редизайн сайта плюс SEO» принимается; «SEO-продвижение плюс
поменять цвет кнопки» отклоняется. Самостоятельное программирование отклоняется и для
Tilda/WordPress, но дополнительный код при создании сайта не мешает приёму.
Магазины на WordPress/WooCommerce со стандартными возможностями подходят. Дизайн
сложного сервиса подходит; разработка такого сервиса под ключ с попутным оформлением — нет.
Обязательная сборка на иной платформе не подходит, дизайн под любую платформу подходит.
Вакансии в штат и конкурсы без гарантированной оплаты отклоняются.

Пустое описание не блокирует понятный заголовок: «Дизайн лендинга» и «Сделать сайт»
принимаются. Непонятные «Доработка сайта» или «Аудит сайта» без уточнения дают `unclear`.
Без названия и описания нельзя получить `accept` по одной категории.
Причина решения сохраняется с указанием основной задачи.

Актуальный набор: `eval/primary-task-projects.json` (66 случаев по правилам от 18 октября).
`eval/projects.json`, `eval/projects-expanded.json` и прежние отчёты сохраняют историческую
разметку: некоторые прежние решения намеренно отличаются от текущей политики.
Бюджет проверяется отдельно. `AI_MIN_SCORE` и сохранённый порог больше не управляют отбором.
Команда `/score` объясняет переход на решения. Числовые поля в базе сохранены для совместимости
с историей: у новых записей это технические 100/0, а не оценка уверенности модели.
После обновления старые записи получают пустые decision/evidence; доступные для обработки
проекты переоцениваются по новой версии правил. Уже просмотренные публикации заново не рассылаются.

По умолчанию `AI_VERIFY_ACCEPTED=true`: только кандидаты `accept` от Pro независимо
перепроверяются резервной моделью Max, без передачи ей решения и объяснения Pro.
Это расходует дополнительные токены Max, но не тратит их на отсеянные Pro проекты.
При ошибке проверяющей модели проект не отправляется и остаётся для повторной обработки.
Если Pro недоступен, после повторов используется Max без дублирующей проверки.
При одинаковых моделях второй запрос также не выполняется.
`AI_VERIFY_ACCEPTED=false` отключает смысловую перепроверку; для отбора без мусора лучше
оставлять её включённой.
Отклик создаётся Ultra только по нажатию
«Написать отклик». В запрос передаются исходный заказ, короткий профиль и до шести кейсов-кандидатов,
отобранных по типу продукта, тематическим совпадениям и платформе. Модель выбирает обычно 1–2 уместных примера;
нерелевантные ссылки добавлять не требуется. Порядок кейсов не считается датой создания.
Роль, платформа и результат кейса не выводятся из URL и не придумываются.
Если заказчик требует больше примеров, чем найдено подходящих подтверждённых кейсов,
бот не уменьшает требование молча и сообщает об этом вместо генерации отклика.

Модель отклика возвращает JSON `body`/`case_ids` и расставляет в тексте маркеры выбранных
кейсов. URL ей не передаются: бот заменяет маркеры точными ссылками и подтверждёнными описаниями
из каталога, сохраняя рядом созданное моделью объяснение релевантности. В VK приходит обычный текст.
Неизвестный ID, пустой ответ, произвольная ссылка, неверный маркер, отдельные
ложные утверждения об изучении материалов или завершение по лимиту вызывают одну попытку исправления. Повторно некорректный отклик не сохраняется и не показывается.
Эти проверки не подтверждают доступность сайтов и не выявляют все возможные смысловые ошибки.
Бот отправляет чистый текст отдельным сообщением, чтобы его можно было скопировать целиком.
Готовый отклик сохраняется в истории проекта и разделяется на короткие абзацы.
Под ним доступна кнопка «Другой вариант». Новый вариант заменяет текст в том же сообщении и сохраняется как текущий
отклик проекта; каждое нажатие обращается к GigaChat и расходует токены.
Карточка не отправляется, пока AI не смог выдать оценку. При
временной ошибке API проект остаётся непомеченным и повторно проверяется в следующем цикле. Это
исключает появление карточек без краткого описания задачи и не теряет проект после единичного сбоя.
Если заказчик перезапускает проект на Kwork и тот же ID снова появляется в общей ленте с новой
датой публикации, бот считает это новой публикацией: повторно проверяет её через AI и при соответствии
фильтрам снова отправляет карточку. Обычные опросы одной и той же публикации дублей не создают.

Затем:

```bash
docker compose up -d --build
docker compose logs -f bot
```

Отдельная проверка ключа и защищённого соединения с GigaChat:

```bash
docker compose run --rm bot gigachat-check
```

Проверка входа в Profi.ru и чтения сохранённой выдачи без отправки сообщений в VK:

```bash
docker compose build bot
docker compose run --rm bot profi-check --check-reauth --check-recovery
```

Команда проверяет начальную загрузку и два повторных цикла с паузой 180 секунд.
`--check-reauth` удаляет cookies только диагностической сессии
и проверяет повторный вход. `--check-recovery` дополнительно закрывает только диагностический
браузер и проверяет автоматический запуск и вход заново. В конце выводятся число карточек
и ссылка на самую свежую. VK-сообщения не отправляются, AI не вызывается, база не изменяется.
Это проверка источника; AI-отбор и доставка уведомлений в VK проверяются отдельно.
Для быстрой проверки входа: `profi-check --cycles 0`. Пауза настраивается через `--interval`
(минимум 60 секунд). Если Profi.ru запросит SMS, captcha или другое дополнительное подтверждение,
команда завершится ошибкой: такой вход автоматически не поддерживается, а сессия вашего обычного
браузера не переносится в бот.

Локальный запуск без Docker:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
python -m playwright install chromium
freelance-bot
```

По умолчанию опрос идет раз в 3 минуты. Первый запуск запоминает текущие карточки и ничего
не отправляет, чтобы не присылать старые заказы. Для теста можно временно установить
`SEND_EXISTING_ON_FIRST_RUN=true`.

## Важные ограничения

- Kwork не предоставляет официальный публичный API для этой задачи. Используется актуальная
  неофициальная библиотека, работающая с API мобильного приложения; после изменений Kwork
  интеграции может понадобиться обновление.
- FL.ru читается из общей HTML-ленты. После изменений разметки площадки CSS-селекторы парсера
  могут потребовать обновления.
- Profi.ru не предоставляет публичный API для такой интеграции. Используется запрос кабинета
  специалиста с его сохранённым фильтром; после изменений Profi.ru интеграцию может
  потребоваться обновить. После истечения cookies бот автоматически входит заново. При неверном
  пароле или запросе дополнительного подтверждения повторные попытки выполняются с растущей
  паузой до часа, чтобы не создавать частые неудачные входы. В одном запросе допускаются
  максимум два парольных входа; успешный обмен токена сам по себе не сбрасывает паузу —
  это делает только успешное чтение защищённой доски заказов.
- Не ставьте интервал меньше минуты: это повышает риск антибот-ограничений площадок.

## Проверка качества AI

`eval/primary-task-projects.json` содержит 66 проверок новых правил: разрешённые направления,
пары с разной основной задачей, три реальные ошибочно принятые SEO-задачи, пустые и длинные
описания, попытку изменить инструкции. Большинство примеров составлены вручную; этот набор
проверяет границы правил, но не заменяет оценку на новых реальных заказах.
Проверка использует платный API, не отправляет сообщения VK и не изменяет базу бота:

```bash
python -m freelance_bot.evaluate_ai --live --limit 66 --output data/eval-current.json
```

`--dataset` задаёт другой набор; `--limit` ограничивает число заказов (по умолчанию 20).
`eval/seo-projects.json` — отдельный исторический набор из десяти SEO-пограничных случаев.
`--responses` также создаёт отклики для ожидаемо подходящих заказов.
Для 15 отдельных сценариев откликов:

```bash
python -m freelance_bot.evaluate_ai --live --responses-only --dataset eval/writer_projects.json --limit 15 --output data/eval-writer.json
```

Отчёт содержит
решения, причины, фактическую модель, версию правил, число ложных допусков и потерь,
precision/recall (null при отсутствии знаменателя). При инфраструктурной ошибке пакет останавливается.
Сохраните отчёты до и после изменения промпта на одном наборе; сравнивайте обе метрики.
Отклики проверяйте вручную: факты, ответы на вопросы клиента, уместность кейсов,
обоснованность следующего шага и объём необходимой правки. Положительный результат unit-тестов
проверяет код, но не подтверждает улучшение качества GigaChat.

После обновления кода пересоздайте контейнер: `docker compose up -d`.
Файлы config должны обновиться вместе с кодом: старый промпт с полем score несовместим
с новой схемой решения. База мигрирует при запуске, старые отклики сохраняются.
