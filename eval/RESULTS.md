# Проверка изменений AI, 11 сентября 2026

Проверены реальные вызовы GigaChat API на синтетических заказах. Сообщения клиентам
и в VK не отправлялись. Рабочая база бота не изменялась.

## Отбор

Набор: `eval/projects.json`, 20 пограничных заказов, из них 5 подходящих.

| Вариант | Ложные допуски | Потерянные подходящие |
| --- | ---: | ---: |
| Первая сокращённая версия, только Lite | 4 | 1 |
| Lite + независимая проверка кандидатов Max | 0 | 1 |
| Та же схема с восстановлением регистра цитаты из источника | 0 | 0 |

Первый вариант — промежуточная сокращённая версия, **не исходный промпт до изменений**.
Последний прогон совпал с разметкой во всех 20 случаях. Набор использовался при доработке,
поэтому результат не является независимой оценкой точности на новых реальных заказах.

Lite ошибочно принимал заставку, отдельный блок, смешанный заказ с логотипом и заказ
этикетки с инструкцией обойти фильтр. Max отсёк эти случаи. Отличие регистра цитаты
больше не отбрасывает подходящий проект: сохраняется фрагмент в исходном регистре.
Перефразированная или выдуманная цитата по-прежнему не проходит.

Локальные подробные отчёты: `data/eval-lite.json`, `data/eval-current.json`,
`data/eval-final.json`. Параметр `AI_VERIFY_ACCEPTED=true` включён по умолчанию.
Он увеличивает расходы на Max только для кандидатов Lite; его можно отключить.

## Отклики

Проверены 15 сценариев из `eval/writer_projects.json`, включая кодовое слово,
вопросы клиента, готовый макет, запрет портфолио, запрос цены/срока и три примера Tilda.
Промежуточные прогоны показали, что одного промпта недостаточно: встречались придуманные
свойства кейсов, сокращённые ссылки, заявления об изучении сайта, неподтверждённом опыте
и нарушение количества примеров.

Исправления:

- Бот подставляет подписи и URL из каталога; модель выбирает только ID.
- Подбор учитывает тип продукта, тематику и платформу; общие макеты Figma не доказывают
  опыт разработки интерфейсов приложения или магазина.
- Явное число примеров и запрет портфолио учитываются схемой и проверяются кодом.
- Проверяются пустые/обрезанные ответы, неизвестные ID, ссылки в основном тексте,
  несколько уточняющих вопросов и конкретные найденные неподтверждённые заявления.
- При нарушении допускается одно исправление. Второй некорректный ответ не показывается.

После последнего полного прогона исправлена отдельная ошибка подбора: «приложите»
больше не считается упоминанием приложения. Повторная проверка этого сценария дала
русский отклик с кодовым словом English и двумя примерами лендингов.

Отчёты: `data/eval-writer-verified.json` (15 сценариев перед последними точечными правками),
`data/eval-writer-codeword.json` (повторная проверка исправленного сценария).
Семантическая проверка откликов остаётся неполной: формальные проверки не гарантируют
идеальную формулировку, уместность каждого вопроса или отсутствие всех возможных выдумок.
Для оценки на рабочем потоке нужен отдельный набор реальных заказов с разметкой пользователя.

## Код и запуск

108 автоматических тестов пройдено: миграция и сохранение истории, новый формат решений,
проверка цитат, независимый верификатор, отказ при его сбое, портфолио и исправление откликов.
Линтер изменённой логики прошёл.

Код, четыре AI-файла конфигурации и `config/portfolio.json` нужно обновлять вместе.
Контейнер: `docker compose up -d --build`. Рабочий бот в этой сессии не перезапускался.
